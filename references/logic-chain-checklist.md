# 核心逻辑链与断点记录

审查链条：现实问题 → 理论矛盾 → 核心研究问题 → 核心概念 → 研究目标 → 研究内容 → 研究方法与证据 → 可能获得的发现 → 理论贡献或知识增量。

## 逐环检查

1. **现实问题**：谁在什么情境中遇到什么可证实的问题？它是背景还是本项目实际要解释的对象？
2. **理论矛盾**：现有解释之间有什么冲突、边界或未解释现象？现实重要性是否被误当成理论缺口？
3. **核心研究问题**：能否用一个可回答的问题表达？它是解释问题、评价问题、机制问题、比较问题还是规范问题？若剥离政策意义、现实意义、热点和术语，是否仍能用 1—2 句话说明学术问题？
4. **核心概念**：定义、边界和观察方式是什么？每个概念属于研究对象、现象、原因、条件、机制、中间过程、结果、价值判断、规范原则还是治理策略？不同章节是否同义使用？
5. **研究目标**：目标能否由项目周期内的证据完成？是否承诺了影响项目无法控制的结果？
6. **研究内容**：每一项对应哪个问题？各部分关系是递进、并列、比较还是条件关系？关系是否有说明？
7. **方法与证据**：材料从哪里来、分析单位是什么、方法执行什么步骤、支持哪种推论、有哪些局限？
8. **可能发现**：设计能产生什么发现？是否把预期发现提前写成事实？
9. **贡献**：相对什么已有知识产生什么增量？贡献是否具体且与设计相称？

## 概念本体与分类层级

| 核心概念 | 文中含义 / 位置 | 逻辑角色 | 所属分类原则 | 如何进入证据或分析 |
|---|---|---|---|---|
| 逐项填写 | 逐项填写 | 对象 / 现象 / 原因 / 条件 / 机制 / 中间过程 / 结果 / 价值判断 / 规范原则 / 治理策略 | 逐项填写 | 逐项填写 |

若一组并列项混合多个逻辑角色，先检查申请书是否明示为不同层级并说明连接；未说明时标记“概念层级混杂”。角色混杂不是只靠统一术语就能修复的表达问题。

## 二元张力是否构成理论问题

遇到技术—人文、效率—公平、赋能—风险、工具—主体等表述，记录：

| 核验问题 | 申请书依据 |
|---|---|
| 这是价值冲突、经验事实还是理论分歧？ | 位置 / 证据 |
| 已有研究或理论之间具体分歧什么？ | 位置 / 文献 |
| 哪个现象或条件没有被解释？ | 位置 / 事实 |
| 项目新增何种解释，怎样与替代解释区分？ | 位置 / 方法 |
| 项目只是主张“平衡 / 加强治理”还是提出可研究的解释？ | 位置 / 判断 |

若后四项缺少依据，标记“现实矛盾尚未转化为理论问题”。

## 逻辑断点格式

【断点】A → B  
【问题性质】学术成立性 / 学术竞争力 / 研究设计 / 证据 / 制度合规 / 提交手续 / 表达技术  
【学术严重度】S / A / B / C / 不适用  
【合规严重度】合规阻断 / 合规风险 / 提交提醒 / 不适用  
【A 的依据】申请书位置及内容  
【缺失的推导】当前材料为何不能推出 B  
【专家疑问】一句具体追问  
【断点类型】表达缺失 / 概念问题 / 理论问题 / 证据问题 / 研究设计问题  
【修复方向】补证据、重界定、重组内容、调整方法或收窄结论

不要把链条当作强制的线性理论模型。某些研究可从理论问题或经验异常起步；应审查其真实推导关系，而非硬套固定顺序。

## 问题—任务—方法—证据映射

| 核心问题 | 研究任务 | 分析对象 / 材料 | 方法步骤 | 可支持的结论 | 局限 |
|---|---|---|---|---|---|
| 逐项填写 | 逐项填写 | 逐项填写 | 逐项填写 | 逐项填写 | 逐项填写 |

若某问题没有任务、某任务没有证据、某方法没有具体用途，或结论强于方法能力，标记相应断点。

## 结论—证据强度核验

| 申请书的结论类型 | 对应检查 |
|---|---|
| 描述 / 归纳 | 对象、材料来源、观察范围和分类程序是否清楚 |
| 关系 / 比较 | 分析单位、变量 / 主题、比较逻辑及替代解释是否清楚 |
| 机制 | 中间过程、过程证据和机制区分依据是否存在 |
| 因果 / 效果 | 干预、比较条件、结果指标、识别逻辑和偏差来源是否说明 |
| 规范 / 价值判断 | 价值前提、规范依据、适用范围和推理过程是否说明 |

不以“缺少样本量”等单一字段自动判错；判断所需证据是否达到申请人实际声称的结论强度。
