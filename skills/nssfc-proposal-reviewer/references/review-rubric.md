# 分层评审标准

## 第一层：5 分钟初审

只看题目、摘要、问题提出、研究对象和总体结构，快速回答：

- 研究对象和边界是否清楚？
- 申请人真正要回答的核心问题是什么？
- 为什么这个问题值得研究、为什么现在研究？
- 题目中的关键词是否进入研究问题和研究内容？
- 第一眼最可能降低评审兴趣的缺陷是什么？

若五分钟内仍无法复述核心问题，应记录为可定位的问题；不要把“读起来费劲”直接写成结构缺陷，先说明是概念、论证缺失还是表达造成的。

## 第二层：结构审查

逐部分检查功能：

| 部分 | 应完成的功能 | 常见失效 |
|---|---|---|
| 题目与摘要 | 准确呈现对象、问题、路径和预期增量 | 题目大而内容窄；摘要与正文不一致 |
| 选题依据 | 从现实或学术情境推出明确问题 | 只有政策背景或热点，没有研究问题 |
| 文献综述 | 说明已知、未解和本项目进入点 | 点名式罗列；无证据宣称空白 |
| 研究目标 | 说明完成后要形成什么认识 | 目标宏大，不能由内容交付 |
| 研究内容 | 将核心问题拆为必要任务 | 并列堆砌；任务之间无接口 |
| 研究方法 | 说明如何取得证据并回答问题 | 方法名称清单；不能识别所声称的关系 |
| 重点难点 | 指出研究真正难以回答的环节 | 把时间、经费或工作量当作学术难点 |
| 创新点 | 给出相对已有知识的具体增量 | 将对象新、术语新、工具新等同知识创新 |
| 前期基础 | 证明团队具备本项目所需能力和条件 | 成果数量多但与任务无关 |
| 计划与成果 | 体现任务、时间、人员、成果相互可行 | 成果承诺远超研究设计或周期 |

## 第三层：逻辑与证据审查

沿核心逻辑链逐环追问，每次只判定申请书当前证据能支持的结论强度。标明哪些是申请书事实、哪些是外部核验结果、哪些是评审推断。

重点辨别：

- 研究缺口是否由文献证据支持，还是由作者宣布？
- 概念能否被定义、观察或分析？指标是否有效代表概念？
- 方法能支持关联、机制、因果或规范判断中的哪一种？
- 结论是否超过样本、材料、时段和识别策略所能支持的范围？
- 关键假设是否说明来源、可检验性及失败后的解释？

## 第四层：竞争性审查

除“能不能做”外，还核验：

- 同类项目已做什么，本项目增加了什么可辨识的知识？
- 为什么现有研究或常规路径不能回答此问题？
- 申请人和团队的既有积累是否匹配关键任务？
- 若不资助，最强的三个学术理由是什么？
- 申请书是否用证据回答了这些理由？

## 跨章节一致性

| 对照项 | 核验关系 |
|---|---|
| 题目 ↔ 研究问题 | 核心概念与对象是否实际进入问题 |
| 摘要 ↔ 正文 | 问题、方法、成果有无漂移 |
| 文献缺口 ↔ 研究内容 | 内容是否直接回答缺口 |
| 研究问题 ↔ 目标 | 目标是否回答而非另起任务 |
| 内容 ↔ 方法 | 每项必要任务是否有可执行方法和材料 |
| 方法 ↔ 证据 | 材料是否能观察所声称的关系 |
| 内容 ↔ 创新 | 创新是否由真实研究任务产生 |
| 基础 ↔ 关键任务 | 已有成果、方法、样本和条件是否对口 |

发现冲突时标记“跨章节逻辑冲突”，给出两端位置及具体不一致。

## 高风险表述

扫描空泛宏大表述、政策口号替代理论论证、无证据的绝对化判断、“首次 / 首创 / 填补空白”、未界定或漂移的概念、题目关键词正文未研究、相关关系写成因果等。高风险词本身不是错误，须检查上下文证据。

## 双轨严重度与问题性质

每个问题除等级外，另标一个主要性质：学术成立性、学术竞争力、研究设计、证据、制度合规、提交手续或表达技术。必要时可补充次要性质；可拆开的学术论证与手续问题应分开写。

**学术严重度**：S 影响核心问题或设计是否成立；A 显著影响贡献、可行性或竞争力；B 为可局部修复的论证 / 设计缺陷；C 为表达和格式问题。纯手续问题的学术严重度记为“不适用”。

判 S 前必须做严重度反事实检查：“如果这个问题完全解决，项目的核心学术成立性会发生实质变化吗？”若不会，通常定为 A 或更低。S 级主要留给核心问题不成立、对象与问题根本错配、主要问题没有可行证据路径、关键机制/因果推论严重超出设计等足以动摇项目的学术缺陷。评审必须定位文本依据，不能只凭主题或术语直接判 S。

**合规严重度**：合规阻断、合规风险、提交提醒或不适用。合规阻断须有明确规则和当前材料证据；规则存在但材料不足以确认时用合规风险 / 待核验。签字缺失、日期、格式、资格、成果硬要求可以阻止提交，但不因此变成“核心研究问题不成立”。

同一问题可以同时有学术等级和合规标签。例如，目标与通知不匹配可能是学术竞争力 A 且有合规风险；签字缺失可以是提交手续、学术严重度不适用、合规阻断（若为最终报送版）。

## 概念本体审查

对每个核心概念注明其逻辑角色：

- 研究对象
- 现象
- 原因
- 条件
- 机制
- 中间过程
- 结果
- 价值判断
- 规范原则
- 治理策略

一组并列概念若混有不同角色，标记“概念层级混杂”，并说明它怎样使研究问题、测量、比较或策略推导失效。角色不同本身不构成错误；关键是申请书是否分层并说明连接关系。

## 理论矛盾深挖

遇到“技术—人文”“效率—公平”“赋能—风险”“工具—主体”等二元张力时，逐项核验：

1. 文本描述的是价值冲突、经验事实，还是理论解释分歧？
2. 已有理论 / 研究之间具体争论什么？
3. 哪个现象或条件仍解释不了？
4. 本项目新增什么解释，证据如何区分它与替代解释？
5. 如果结论只是“需要兼顾 / 平衡 / 加强治理”，是否只是规范主张而非学术解释？

无法说明理论分歧或解释对象时，标记“现实矛盾尚未转化为理论问题”。不要因为使用二元词组就自动认定存在理论问题。

## 框架形式主义检查

对三维框架、四层模型、宏观—中观—微观、主体—技术—场景等结构，检查：

- 分类原则是什么，各维回答哪一类问题？
- 在其声称范围内是否尽量穷尽、彼此边界是否可辨？
- 各维是否处于同一逻辑层级？若不是，是否明确说明各自层级和接口？
- 框架是否由文献、理论或经验材料支持？
- 各维是否进入资料收集、编码、比较、分析或策略设计？
- 删除某一维后，研究问题或结论会如何变化？

“结构整齐”本身不构成问题；如果分类原则不清、不同层级被并列，或结构没有参与后续分析，标记“框架形式主义风险”。

## 结论强度—证据强度匹配

根据申请人准备得出的结论判断方法要求，不机械用单一方法清单评判：

| 结论强度 | 最低核查点 |
|---|---|
| 描述 / 归纳 | 研究对象、资料来源、观察范围、分类 / 描述程序及边界 |
| 关系 / 比较 | 分析单位、变量 / 主题、比较组或比较逻辑、替代解释 |
| 机制 | 中间过程、时间 / 过程证据、竞争性机制及区分依据 |
| 因果 / 效果 | 干预 / 暴露、比较条件、结果指标、识别逻辑及偏差来源 |
| 规范 / 价值判断 | 价值前提、规范依据、适用对象、冲突价值和推理步骤 |

样本量、工具、实验细节只在与结论类型和学科范式相关时追问。关键问题是：现有方法和证据能否支持申请人实际声称的结论。

## 报告排序

完整报告依次组织为：学术核心风险（3—5 项）、研究设计风险、创新与竞争力、制度合规阻断项、B/C 级及表达问题。若没有 S 级学术问题，明确写“未发现 S 级学术问题”；合规阻断项另列，不能顶替学术命门。
