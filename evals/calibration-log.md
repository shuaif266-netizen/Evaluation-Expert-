# Reviewer 校准记录

## 2026-10-02：首次正式盲测后的系统校准

本记录保留评审系统层面的判断变化，不包含申请书原文、申请人身份或个案评审报告。

### 暴露的问题

- 学术成立性与手续问题曾被置于同一严重度池，导致签字、字段等容易核对的事项压过学术命门。
- 框架审查能发现结构映射缺失，但尚未稳定识别概念是否属于同一逻辑层级。
- “技术—人文”等二元张力有时被直接当成理论问题，未继续追问解释分歧和知识增量。
- 方法判断容易落入固定清单；应先看作者要做出描述、关系、机制还是因果/效果结论，再判断所需证据。
- 学术问题剥离测试和框架实际用途检查需要进入每次评审流程。

### 保留的能力

- 逻辑链及“研究不足到核心问题”的断点识别。
- 问题—任务—方法—证据匹配、跨章节一致性和反向否证。
- 区分材料未证明与客观不存在。
- 高风险事实核验和 A/B/C 来源证据边界。
- 以位置、依据、专家疑问、根因和修改方向组织重大问题。

### 校准后做法

- 学术严重度和合规严重度双轨；纯手续的学术严重度为不适用。
- 为核心概念标记逻辑角色，并检查分类层级。
- 对理论张力追问现有解释分歧、未解释现象和项目新增解释。
- 以结论强度决定方法与证据要求。
- 完整报告先列学术命门，再列设计、竞争力、合规阻断和 B/C 问题。
- 增加剥离热点/政策语言后的学术问题与框架形式主义检查。

### 防止过拟合

规则写成跨领域的问题类型和证据判断，不保留个案主题、特定表格字段或固定方法清单。合规阻断必须以本次提供的明确规则为依据。后续校准至少覆盖不同学科、不同范式和“无严重问题”的案例。

## 2026-10-02：v0.2.0 Plugin 工程审计

- 触发：v1.0 前审计要求检查 Marketplace 固定版本、Skill 激活、材料指令隔离和长期校准机制。
- 发现：旧 Marketplace 的 plugin source 再指向 GitHub main，外层固定 ref 不能保证最终插件内容固定；评审 Skill 也缺少显式材料指令隔离。
- 判断：Marketplace ref 漂移和材料注入隔离属于可跨项目复用的工程/安全问题；新增研究范式、自适应报告和 S 级校准属于规则澄清。
- 修改：Marketplace source 改为快照内相对路径；新增 Activation 与 Prompt Injection Eval；新增 Calibrator Skill、版本脚本和发布清单。
- 回归：本记录只确认目录、路径和构建层面检查。模型行为 Regression 需在独立干净会话中记录，不把静态检查冒充语义通过。
- 过拟合控制：旧七个案例及 good proposal 保留；新增强机制案例检验结论与证据匹配，不将个案题材写入通用规则。

## 2026-10-02：Codex CLI 0.159.2 合成回归

- 测试环境：先确认默认 profile 未安装 Evaluation Expert；从 v0.2.0 tag 安装。Reviewer 行为在只有合成 proposal.md 的临时项目中运行，该项目没有本地 AGENTS.md、.codex/skills 或 knowledge。
- Regression：case01—case08 与 case_prompt_injection 均运行。核心问题、概念层级、结论—证据、创新、合规分轨、跨范式、强机制设计和注入隔离均符合期望；case05 quick/full 均未发现 S/A，只列一项 B 级比较边界。
- Activation：同行评审隐式请求触发；普通论文润色、题目生成、商业文案改写未转成 Reviewer；混合诊断/修改先诊断再给表达建议；题目单独咨询被限制在题目层级；Calibrator 触发并将样本量误判例归为 False Positive、Generalizable，但不因单一合成案例修改主 Skill。
- Eval 夹具修订：case08 首轮缺少文献缺口材料，Reviewer 合理地提示学术竞争力依据未呈现。为让该案例实际测试“强机制设计的证据匹配”而非“文献缺口缺失”，给它加入明确标注的合成文献地图后重跑；Reviewer 未报 S/A 设计或证据问题，只提示“持续教研能力”的观察判据需界定。未据此修改主 Skill。
- 限制：以上均为合成测试，不是独立真实申请书或真人专家意见；不作为人类校准轮次。完整自动输出保存在受控临时测试目录，不纳入发布包。
